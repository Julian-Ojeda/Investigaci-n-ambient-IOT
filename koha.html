Koha y RFID en la UNAHUR

Cómo conectar nuestro sistema RFID con el Koha de la biblioteca: qué versión tiene, qué permite hoy, qué decisión hay que tomar y por dónde empezar.

Lo esencial Lectura de 1 min · detalle completo, 10 min

La biblioteca usa Koha 22.11.27. Con esa versión se puede integrar RFID por SIP2 desde hoy, pero el plugin de mostrador y el préstamo por API requieren actualizar Koha a la 25.11 o posterior.

25.11

Lo que ya está

  • Catálogo y API REST activos en biblioteca.unahur.edu.ar.
  • La API permite buscar ejemplares por código de barras.
  • Koha 22.11 trae un servidor SIP2.

Riesgos

  • La 22.11.27 está varias actualizaciones de seguridad atrás: salieron al menos hasta la 22.11.34.
  • Sin actualizar Koha, la API no registra préstamos ni devoluciones.
  • La obra de ampliación de la biblioteca define dónde van los arcos.

Próximo paso sugerido

Reunión con TI de la UNAHUR para acordar tres cosas: si se actualiza Koha y cuándo, habilitar SIP2 y qué hardware RFID ya se eligió.

02

La decisión: actualizar Koha

Dos caminos y una recomendación

02 · La decisión

¿Actualizar Koha antes o integrar con la versión actual?

Camino A

Actualizar a Koha 25.11 o posterior

  • Permite usar el plugin RFID abierto en el mostrador: varios libros a la vez y antirrobo automático.
  • La API pasa a registrar préstamos.
  • Pone al día las correcciones de seguridad.
  • Costo: trabajo de TI, pruebas y revisar las personalizaciones del catálogo.
Camino B

Seguir con Koha 22.11

  • Préstamo y devolución por SIP2, desde una pantalla de nuestro sistema.
  • Como alternativa simple, el lector escribe el código en Koha como si fuera un teclado, de a un libro por vez.
  • La API queda solo para consultas.
  • Costo: la pantalla de mostrador la tenemos que hacer nosotros.

Recomendación

No esperar la actualización para empezar. SIP2 funciona en las dos versiones y es la misma vía que después usan el quiosco de autopréstamo y el buzón, así que ese trabajo se aprovecha igual. En paralelo, proponer a TI actualizar Koha, por seguridad y para sumar el plugin en el mostrador.

SIP2

La vía que funciona con la versión actual

04 · SIP2

El estándar de los quioscos, y nuestra vía de entrada

Koha trae su propio servidor SIP2. Es la vía que usan los quioscos de autopréstamo y los buzones de devolución del mercado. Manual de Koha

Qué hace TI

Completa SIPconfig.xml y ejecuta koha-enable-sip y koha-start-sip en el servidor.

Cuentas

Cada equipo entra con un usuario de Koha. El manual recomienda darle solo permiso de circulación.

Sedes y reglas

La biblioteca se declara con su código de sede y define qué operaciones acepta, por ejemplo si permite renovar.

Mensaje SIP2

Límites: SIP2 solo cubre circulación; no sirve para catalogar ni para inventario masivo. Además viaja sin cifrar, así que conviene que el servidor y los equipos se comuniquen por la red interna o por un túnel cifrado.

05 · API REST

Acceso y permisos

OAuth2

Solo el flujo client credentials: credenciales para una aplicación, sin inicio de sesión de una persona. El token se pide a /api/v1/oauth/token. Bug 20402 y API de la UNAHUR

Permisos heredados

Cada credencial queda atada a un usuario de Koha y tiene sus mismos permisos. Conviene pedirle a TI un usuario técnico solo con lectura y circulación.

Habilitación

La autenticación básica y OAuth2 se activan en las preferencias del sistema. No sabemos si en la UNAHUR están activas. A confirmar con TI

06 · El plugin RFID abierto

Dónde encajaría nuestro sistema

ByWater Solutions publica un plugin de código abierto (GPL-3, versión 0.10.0 del 29/10/2026). Koha no habla con el lector: el navegador del bibliotecario consulta a un servicio en la misma PC, y ese servicio sería el nuestro.

  1. Hardware

    Lector RFID

    Pad sobre el mostrador que lee las etiquetas de los libros.

  2. Nuestro sistema

    Servicio local

    Traduce cada etiqueta a código de barras y maneja el bit antirrobo.

  3. Plugin en Koha

    Navegador

    Toma los códigos y ejecuta préstamo, devolución o inventario.

  4. Servidor

    Koha

    Registra la operación como si se hubieran escaneado los códigos.

Versión mínima: desde la versión 0.9.0 (21/10/2026) el plugin declara Koha 25.11. Las versiones anteriores no publican un mínimo en su código, así que no hay garantía de que funcionen en la 22.11. Historial del repositorio

06 · El plugin RFID abierto

Qué tendría que responder nuestro servicio

El plugin define tres operaciones por proveedor. Este es el formato que usa para Tech Logic CircIT, que permite configurar el puerto:

GET  http://localhost:{puerto}/Temporary_Listen_Addresses/alive
     → {"status": true, "statuscode": 0}

GET  …/getitems
     → {"items": [{"barcode": "0001234", "security": false}]}

GET  …/setsecurity/0001234/true      (activa el antirrobo)

Qué cubre

Préstamo y préstamo por lote, devolución, renovación, transferencias, inventario y listas. Desactiva el antirrobo al prestar y lo activa al devolver; se detiene si hay una reserva o algo para confirmar.

Cómo sumarnos

Agregar un adaptador propio: un objeto con cuatro funciones en rfid.js. Se puede proponer al proyecto o mantener una copia propia. Hay que verificar que el navegador permita llamar a localhost.

HF o UHF, y qué se graba en la etiqueta

07 · Etiquetas y lectores

HF o UHF: la decisión que define la compra

Si el proyecto ya eligió hardware, esta sección sirve para confirmar que la elección sea coherente con la norma de bibliotecas.

HF · 13,56 MHz
UHF · EPC Gen2
Uso en bibliotecas
El estándar histórico: casi todos los sistemas en producción en EE.UU. eran HF. Informe de la ALA, 2012
Minoritario en bibliotecas; las generaciones nuevas mejoraron cerca de metal y agua.
Norma de datos
ISO 28560-2: el modelo de datos para bibliotecas, sobre etiquetas ISO 15693.
ISO/TS 28560-4:2023: especificación técnica para etiquetas con memoria en bancos, como las Gen2.
Lectura
Corto alcance: mostrador, pad y quiosco.
Más alcance: inventario rápido de estanterías y arcos más anchos.

Para la UNAHUR: pedir al proveedor de etiquetas que grabe con la norma ISO 28560 que corresponda a la frecuencia, y probar la lectura sobre las estanterías y los carros reales, que suelen ser de metal. Ver el tema Trazabilidad sobre metal.

08 · Plan para la biblioteca

Cuatro fases, de menor a mayor alcance

Fase 0 · Definiciones

Reunión con TI y la biblioteca

Plan de actualización de Koha, habilitación de SIP2, usuario técnico para la API, hardware elegido y en qué edificio se arranca.

Fase 1 · Mostrador

Piloto de préstamo y devolución

En un Koha de prueba de la misma versión: nuestro sistema presta y devuelve por SIP2, y maneja el antirrobo de la etiqueta. Si Koha ya se actualizó, se suma el plugin.

Fase 2 · Colección

Etiquetado y arcos

Grabado de etiquetas con el código de barras de cada ejemplar y arcos de seguridad, coordinados con la obra de ampliación.

Fase 3 · Autoservicio

Autopréstamo, buzón e inventario

Quiosco y buzón por SIP2; inventario con lector de mano, contrastado contra Koha por la API.
